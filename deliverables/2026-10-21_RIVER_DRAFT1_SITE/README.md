## 第四版（10-22）：插件运行问题 + 两处场地批注
插件改到 **0.9.4**（`dist/ProgramDiagram-0.9.4.zip`），对应你们跑 DRAFT_1 时发现的问题：
- **玻璃 = 外皮，室内其余是 circulation**：插件对每个主楼层，用竖立的玻璃和本层体块围出外皮。外皮内没有 program 的部分自动生成 CIRCULATION，建了的房间按"体积小者优先"保留。中庭、楼梯等楼板开洞保持开敞；玻璃没有围合的地方仍是室外。模型里不需要再手工补 circulation 体块。
- **2' 的 interactive 丢失**：原因是薄体块的上限是 2.0'，你们的 interactive 是 2.0–2.1'，被漏掉了；上限改为 2.5'。地面上的薄体块只有在玻璃外皮外才当作场地铺装，所以 dining hall 等室内的 2' 平台算 program。薄体块归到离板底最近的楼层，不会被抬到夹层。`INTERACTIVE` 图层自动对应 Interaction。
- **轴测高度**：爆炸轴测里体块按原 block 高度（不超过本层层高）；circulation / interaction 平铺在楼板上。
- **剖面楼板**：楼板只画在剖切到建筑的范围内。模型里的整层大楼板只用来判断开洞，不再把楼板延长到没剖到的地方。夹层楼板只画在从该夹层起步的体块（停车甲板）下面。主楼层的体块和色条一直画到下一个主楼层，不再在夹层处截断。爆炸轴测中夹层上不再出现玻璃。
- **平面文字**：房间名统一用 CORE LAB 的字号（`fonts.label`，`plan.labelUniform`），放不下的用引线。首层平面不再标楼上（停车楼屋顶等）的场地名称。
- **site context 消失**：在 Linux 上用同一个模型复现时 context 正常（见检查 PDF）。推测是你们 Rhino 里 SITE CONTEXT 的图层隐藏着，插件第一次运行时第 ① 页的 Use 默认不勾。这个模型的设置里已全部勾上；如果你们的设置文件更新，请在第 ① 页确认。

模型（在第三版基础上）：
- 停车楼西侧的窄条 greens（1f02ebc1）改为 LOADING 硬质铺地。
- 西南角沿西边界的几条 greens 和二次落客岛（a0dd3665、3f41822b、0faf9be8、67c09ee7）改为硬质铺地。
