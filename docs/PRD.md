# PRD：Rhino 体块 → Program Diagram 生成器（Plan / Section / Axon）

v0.3 · 2026-10-09 · 状态：草案（已根据团队真实工作流调整）

## 0. 本版主要变化
团队的实际做法是：在 Rhino 里直接拉 program 体块并按颜色区分，再导出平面、剖面和轴测（参考 Downtown Concept / Forum 的草稿）。因此本版做了以下调整：

- **主输入**：从 DXF 改为 **Rhino 3D 体块模型**。DXF 保留为第二阶段的备用输入。
- **大幅简化**：不再需要"识别边界、补缝、分层"。体块本身就是边界，楼层可以从标高得到，program 由图层或颜色决定。
- **难度和周期都下降**，并且同一个模型可以出三类图。剖面里的剖切 / 背景关系可以用几何计算准确判断。

## 1. 目标
> Rhino 体块模型 → 自动整理（楼层、program、剖切）→ 在 Rhino 中确认和修改 → 输出分图层、可继续编辑的 Illustrator 文件

| 输出 | 说明 |
|---|---|
| **Plan**（多层平面排版） | 每层按标高水平剖切，得到 program 色块，排成 B1 / L1 / L2 … 的网格，带场地底图 |
| **Section** | 沿剖切线竖向剖切，剖到的体块画成圆角色条，背景按投影绘制 |
| **Axon** | 直接用 3D 体块生成，提供爆炸式和叠合式 |
| **面积统计**（附带） | 按 program 汇总面积，生成表格和饼图（类似 PROGRAM SF 那张） |

所有输出统一换成**公司标准图例**的颜色和字体。草稿阶段的临时配色会在导出时自动规范化。

**成功标准**
- 从模型到三类 AI 图共 ≤ 15 分钟
- 方案改动后重新导出 ≤ 2 分钟，手调内容不丢失

## 2. 范围
| 本期做 | 本期不做 |
|---|---|
| Rhino 8 插件（Python 3 + Eto 面板） | Revit 输入 |
| 楼层自动识别；program 映射（图层或颜色 → 公司图例） | 实时双向同步（AI 改了回写 Rhino） |
| 剖切线拾取；剖到 / 未剖到自动判断 | 渲染图（Exterior View 继续用现有渲染流程） |
| 同一模型中多方案对比（option 1 / 2 并排） | 流线和安全分区的自动生成（作为手动叠加图层） |
| 导出：Illustrator 脚本（生成原生分图层 .ai）和 SVG 预览 | DXF 输入（放到第二阶段，沿用 v0.2 的识别方案） |

## 3. 用户流程（全部在 Rhino 内完成）
1. 运行命令 `ProgramDiagram`，选择体块（或按图层全选）。打开侧边面板。
2. **楼层**：系统按体块的底标高聚类出楼层，表格列出层名、标高和层高，可直接改名、合并或拆分。
3. **Program 映射**：表格列出模型里出现的每个"图层或颜色"，自动匹配到公司图例，用户逐行确认或改选。
   - 映射结果保存在模型中，下次打开不用再选。
4. **标签**：默认使用对象名称（Object Name），否则使用 program 名。双击可在表格中修改。
5. **剖切**：拾取一条或多条剖切线（如 A、B），设置可见进深。
6. **预览**：选择 Plan、Section 或 Axon 后，在 Rhino 视口中叠加 2D 预览；不确定项高亮显示。
7. **导出**：生成 `.jsx`，在 Illustrator 中运行，得到 .ai。
   - 方案改了以后重新导出，只更新生成的图层，手调图层保留。

## 4. 功能需求

### F1 读取与楼层识别
- 支持的对象：闭合 Brep、Extrusion、Mesh。非闭合对象列入不确定项。
- 楼层识别：
  - 体块底标高按容差聚类，得到楼层；
  - 跨多层的体块（如两层高的 Auditorium）记为跨层对象，不拆分；
  - 地坪 ±0 可在面板中设置。
- 多方案：按顶层图层（如 `OPT-1`、`OPT-2`）或 Rhino 的图层状态区分，可选择单独导出或并排导出。

### F2 Program 映射
- 优先级：
  1. 图层名或对象的 User Text 匹配公司图例（推荐的建模约定见第 8 节）；
  2. 按显示颜色就近匹配图例颜色；
  3. 都匹配不上则标为 `Unassigned`。
- 特殊类型：`SHELL` 和 `PENTHOUSE` 输出为白底加细黑框；`VOID` 和 `CORE` 输出为虚线框，用于中庭、核心筒、Micron Gallery 这类透明空间。

### F3 不确定项
以下情况高亮，并列出清单：
- 体块未闭合
- 体块之间重叠（同层同位置有两个 program）
- 未匹配到 program
- 体块底标高不在任何楼层上
- 体块极小（可能是误建）

### F4 Plan 输出
- 每层在"标高 + 1.2 m"处水平剖切，得到 program 色块，标签居中。
- 核心筒用深灰色。
- 场地图层（道路、街区、树）作为浅灰底图，每层共用。
- 排版方式：网格排列，可设置列数；层名放在左上角（如 `B1`、`L1`、`TOWER`）；标准层可以合并为一张。

### F5 Section 输出
- 剖切面与体块求交，得到截面轮廓，画成圆角色条，标签居中。
- 楼板线：每层画通长的双细线，比体块略长。
- 地坪线；地下部分画基坑轮廓。
- 剖切线之后、可见进深之内的体块和环境建筑：只画投影轮廓，用浅灰虚线。核心筒投影用虚线竖线。
- 坡道、楼梯：放在 `CIRC` 图层的对象，画成斜线或楼梯纹样。
- 风格同时满足 v0.2 中的成品样式（参考 Research Building 的 Section A / B）：黑色粗外轮廓、红色用地红线、高度标注。

### F6 Axon 输出
- 轴测角度可选：等轴测，或自定义方位角和仰角。
- **叠合式**：完整体块，外轮廓用粗线，program 颜色铺在侧面和顶面，可设透明度。
- **爆炸式**：按层沿 z 方向拉开，楼板白色加黑色粗轮廓，program 色块铺在顶面；Level 引线放在右侧一列。
- 场地铺绿底，街道用灰色粗箭头加白字（参考 Research Building 的体量轴测）。
- 消隐：按体块排序后用画家算法绘制；复杂遮挡交给 Rhino Make2D 处理。

### F7 面积统计
- 按 program 和楼层汇总面积（GSF，以剖切面积计）。
- 输出 CSV，以及一张饼图或条形图（同样进 AI）。
- 支持显示指标，例如 "Shell space 占比 30%"。

### F8 导出（Illustrator）
沿用 v0.2：
- 每个 program 一个全局色板；
- 文字使用段落样式；
- 对象按稳定的名字命名，重新导出时原位更新；
- `_MANUAL` 图层永不覆盖。

图层结构：
```
_MANUAL / ANNO / LABELS / PROGRAM(L1…Ln) / OUTLINE / SLAB / BEYOND / CONTEXT(SITE, GROUND)
```
另加 `OVERLAY` 图层，用于 security layers 这类手画叠加内容。

  | Open Office | `#B1D7DE` | Lobby / Break | `#EFB7D7` |
  | Lab | `#F7A238` | Interaction | `#DFAFBF` |
  | Lab Support | `#F5CB78` | Clinic | `#888DB3` |
  | Circulation | `#FDF5D1` | Clinic Support | `#BCC0DB` |
  | Building Support | `#D8D8D6` | Vivarium | `#AF885D` |
  | Vivarium Support | `#BDA78D` | Vivarium Procedure | `#EAE3C7` |

  新增：Shell 和 Penthouse（白底黑框），Unassigned（灰色加斜线）。
- **线型和字体**：沿用 v0.2 的第 5.2 节。草稿中的 Futura 风格标题字体属于版式模板，不在生成范围内。

## 6. 参数（面板默认值）
| 参数 | 默认值 |
|---|---|
| 楼层聚类容差 | 0.5 m |
| Plan 剖切高度 | 标高 + 1.2 m |
| Section 可见进深 | 30 m |
| 色条内缩 | 0.12 × 层高 |
| 色条圆角 | 6 pt |
| Axon 方位角 / 仰角 | 等轴测 |
| 爆炸间距 | 1.5 × 层高 |
| 体块透明度（叠合式） | 0% |
| 出图比例 | 1/32" = 1'-0" |

## 7. 技术方案
| 模块 | 实现 |
|---|---|
| 几何计算 | Rhino 8 内的 RhinoCommon：Brep 与平面求交、投影、Make2D |
| 界面 | Eto 侧边面板；视口预览用 DisplayConduit |
| 数据 | `diagram.json`，包含楼层、program、2D 几何、参数，保存在 3dm 的 DocumentUserText 中 |
| 导出 | Illustrator ExtendScript（.jsx），数据以 JSON 形式内嵌，与 v0.2 相同 |
| 分发 | Rhino 包管理器（Yak）安装，或直接放 Python 脚本 |
| 二期 | 把核心算法抽成 `rhino3dm` 加 Python 的独立服务，接入 DXF 输入和浏览器界面 |

## 8. 建模约定（一页纸，发给团队）
1. 每个 program 体块是**闭合实体**，一般一层一块；跨层空间可以建成一块。
2. 图层：`PRG::<Program>`（名称与公司图例一致），如 `PRG::Lab`、`PRG::Lab Support`。
   - 也可以沿用现有的颜色习惯，由插件做颜色映射，但不推荐。
3. 对象名称（Object Name）就是标签，如 `TYPICAL LAB FLOOR`、`PARTNER / INCUBATOR SHARED SPACE`。
4. 其他图层：
   - 核心筒：`PRG::Core`
   - 中庭、挑空：`PRG::Void`
   - 坡道、楼梯：`CIRC`
   - 场地和周边建筑：`CTX::Site`、`CTX::Building`
   - 剖切线：`SEC::A`、`SEC::B`
5. 多方案：每个方案放在 `OPT-1`、`OPT-2` 顶层图层下。

## 10. 风险与待定问题
- 现有模型不一定遵守建模约定：
  - 首次使用时，颜色映射和对象名会不全；
  - 需要一个"一键整理"工具，把旧模型整理成约定的格式。
- Axon 的复杂遮挡（悬挑、退台交错）用画家算法可能出错，需要退回 Make2D，速度较慢。
- 需要提供：
  - Downtown Concept 的 3dm 模型，作为测试样本；
  - 成品 AI 原文件，用来校准样式；
  - 确认团队使用的是 Rhino 8（Mac 还是 Windows）。
